# AGY Control

AGY Control is started automatically by the MCP client (Claude Code, Codex, OpenCode, or Hermes) and is available throughout the session. Use `agy_workflow_start` for two or more independent or dependent bounded tasks, research/analysis/validation, or work that benefits from parallelism; use `agy_delegate` for one implementation task. Use `delegation_mode="automatic"` only for nontrivial bounded implementation work in a clean, committed repository with explicit allowed paths and deterministic tests. Keep worker changes isolated, inspect reports and complete diffs, and use `agy_apply` only after explicit user approval.

Let AGY workflows own scheduling, dependencies, retries, context handoff, progress, and cancellation; The commander remains responsible for task decomposition, synthesis, final decisions, and applying patches. Do not delegate tiny edits, broad unbounded exploration, final teaching or clinical reasoning, grading, or mastery decisions. Read-only workflow workers cannot modify files, run commands, access the network, or spawn more workers. AGY implementation workers are patch-only or evidence-only support; the commander remains responsible for final decisions.
